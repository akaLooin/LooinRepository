# Phase 2-1: 반복 거래 · 백업/복원 · DB v2

## 구현한 것

### 반복 거래 (정기 결제·급여)
- 규칙(`core/recurring/Recurring.kt`)
  - 매월 N일(1~31, 없는 날짜는 말일) 또는 매주 X요일
  - 간격: 1·2·3·6·12개월, 또는 1·2주
  - 시작일·종료일, 사용 중 켜기/끄기
- 돈 관리 탭 → "반복 거래 +"로 만들고, 목록에서 눌러 수정·삭제합니다.
- 규칙이 만든 거래는 **예정** 상태이고 `↻` 표시가 붙습니다. 거래 메뉴의 "반복 규칙 보기"로 규칙 화면에 갈 수 있습니다.
- 중복 방지
  - 규칙마다 "어디까지 만들었는지(`generatedThrough`)"를 기록합니다. 사용자가 지운 발생분은 다시 생기지 않습니다.
  - DB에 (규칙, 원래 발생일) 고유 인덱스를 둬서, 여러 번 생성해도 같은 날짜 거래가 두 번 생기지 않습니다.
- 규칙 수정·삭제는 **오늘 이후의 미처리 예정분**에만 적용합니다. 완료·취소한 기록은 그대로 둡니다.
- 활성 반복 규칙이 쓰는 계좌는 보관할 수 없습니다.
- 반복 규칙이 만든 예정 지출도 일반 예정 지출과 똑같이 계산합니다. 예산 안에서 확보되고(이중 차감 없음), 예상 잔고에만 반영되며 실제 잔고는 바꾸지 않습니다.

### 백업 · 복원
- 설정 → 데이터 → "백업 파일 만들기"를 누르면 JSON 파일을 원하는 위치(내부 저장소, 클라우드 드라이브 등)에 저장합니다.
  - 파일에는 계좌·카테고리·거래·예산·반복 규칙·설정과 검증용 요약값(건수, 금액 합계)이 들어갑니다.
- "백업에서 복원"은 다음 순서로 동작합니다.
  1. 형식·버전·요약값·참조 무결성을 먼저 검사합니다.
  2. 확인을 받은 뒤 한 트랜잭션으로 전체를 교체합니다.
  3. 교체 후 요약값을 다시 비교합니다. 다르면 되돌립니다.
- 손상되거나 편집된 파일, 다른 앱의 파일, 미래 버전 파일은 거부하고 기존 데이터는 그대로 둡니다.

### DB 스키마 v2
- `recurring_rules` 테이블과 거래의 `recurring_id`·`recurring_occurrence` 열을 추가했습니다.
- Room 자동 마이그레이션(1→2)을 씁니다. v1 데이터가 그대로 남는지 `MigrationTest`로 검증했습니다.

## ⚠️ 확인이 필요한 규칙 (제안 기본값으로 구현)

1. **생성 범위**: 주 회계 기간 기준으로 다음 기간의 마지막 날까지 예정 거래를 미리 만듭니다. 앱을 열 때와 날짜가 바뀌어 다시 돌아올 때마다 채웁니다.
2. **과거는 채우지 않음**: 시작일이 과거여도 오늘 이전의 발생분은 만들지 않습니다. 밀린 예정 거래가 한꺼번에 쌓이는 것을 막기 위해서입니다.
3. **자동 완료 없음**: 자동이체라도 '예정'으로 만들고, 실제로 나갔을 때 사용자가 완료 처리합니다(완료 시 실제 금액·날짜 수정 가능).
4. **수정 시 미래 예정분 교체**: 사용자가 따로 날짜·금액을 고친 미래 예정분도 규칙을 수정하면 새 규칙으로 다시 만들어집니다.

# Phase 2-2: 캘린더 확장 · 예정 거래 알림 · 미리보기 빌드 (2026-11-13)

## 캘린더 (기획서 "추후 확장" 항목)
- **날짜 아래 표시 방식 선택**: 금액 보기(수입·지출) / 잔고 보기(그날 잔고) / 점만 보기. 기기별로 기억
- **날짜별 잔고** (`BalanceCalculator.balanceOn`)
  - 지난 날짜: 그날 끝 시점의 실제 잔고(그날까지 완료된 거래만). 처리하지 않은 지난 예정 거래는 넣지 않음
  - 오늘 이후: 현재 실제 잔고 + 그날까지의 예정 거래(= 예상 잔고)
  - 대상: 현금성 원화 계좌(홈의 '실제 보유 잔고'와 같은 범위)
  - 계좌를 만들기 전 날짜는 초기 잔고로 보인다(초기 잔고를 시작점으로 보기 때문)
- **반복 결제 표시**: 반복 거래가 있는 날짜의 동전 오른쪽 위에 ↻
- 선택한 날짜 아래에 "이날 끝 잔고"(지난 날) / "이날 예상 잔고"(오늘 이후)

## 예정 거래 알림 (Android)
- 설정 → 알림 → "예정 거래 알림"(기본 꺼짐). 켤 때 Android 13+ 알림 권한을 요청
- 하루 한 번(오전 9시쯤) 기기 안의 데이터만 확인해, **오늘 예정**이거나 **처리하지 않은 지난 예정** 거래가 있을 때만 알림
  - 예: "오늘 예정 2건 · 지난 예정 1건 / 오늘 나갈 돈 550,000원 · 월세, 급여, 통신비"
- 내용 결정은 `core` 의 `ReminderPlanner`(테스트 있음), 실행은 WorkManager. PC 는 설정 항목을 숨김

# Phase 2-3: 저축 목표 · 예산 이월 규칙 확정 (2026-11-13)

## 사용자 결정
1. **예산 이월 없음** — 기간마다 예산은 독립. 남은 예산을 다음 기간에 더하지 않고, 초과 사용도 다음 기간에서 빼지 않는다(`SavingsAndRolloverTest.noBudgetRollover`).
2. **저축 목표 배정액은 사용 가능 금액에서 빼 둔다.**

## 저축 목표
- 돈 관리 탭 → "저축 목표 +". 목표 이름·금액·색, 돈을 둘 곳 선택
  - **생활비 계좌에서 떼어 두기**(기본): 실제 잔고는 그대로, '생활비로 사용 가능한 금액'에서만 뺀다
  - **생활비 계산 대상이 아닌 계좌**(예: 적금 통장): 그 돈은 원래 사용 가능 금액에 없으므로 **다시 빼지 않는다**(이중 차감 방지)
- 목표를 누르면: 진행률, 떼어 두기 / 배정 해제(배정된 금액까지만), 배정 기록(지우지 않고 쌓임), 편집, 보관
- **보관**하면 배정이 풀려 사용 가능 금액에서 더 이상 빼지 않는다. 기록은 남는다
- 사용 가능 금액 계산 근거에 "저축 목표 배정" 줄이 추가된다
- 예상 잔고·실제 잔고·순자산에는 영향 없음(돈을 옮기는 것이 아니라 용도를 정해 두는 것)

## 데이터
- DB v3: `savings_goals`, `savings_allocations` 추가(자동 마이그레이션, v2→v3 테스트)
- 백업 형식 2: 저축 목표 포함. 형식 1 파일도 읽는다(목표 없음). 형식 2 파일은 옛 앱에서 "앱을 업데이트하세요"로 거부된다

# Phase 2-4: 즉시 화면 전환 · CSV 내보내기/가져오기 (2026-11-13)

## 화면 전환
- 탭·상세·설정 화면이 바뀔 때 페이드 없이 **즉시** 바뀐다(Navigation 전환 애니메이션 모두 없음). 회귀 테스트 `InstantTransitionTest`

## CSV 내보내기 (설정 → 데이터)
- 모든 거래를 CSV 로 저장. **UTF-8 BOM** 이라 엑셀에서 바로 열린다
- 열: 날짜, 실제 처리일, 상태, 유형, 금액, 통화, 출금 계좌, 입금 계좌, 카테고리, 메모, 반복
- 백업(JSON)과 달리 **복원용이 아니라** 엑셀 정리·다른 앱으로 옮기기용. 계좌 초기 잔고·예산·반복 규칙·저축 목표는 들어가지 않는다

## CSV 가져오기 (설정 → 데이터)
- 파일을 고르면 **미리보기**: 새 거래 N건 / 중복 M건 / 오류 K건(줄 번호와 이유). 확인을 눌러야 저장되며 **새 거래만 추가**한다(기존 데이터는 지우지 않음)
- 읽는 형식
  - 이 앱이 내보낸 CSV(왕복 시 모두 중복으로 판정 → 0건 추가)
  - 은행 거래내역: 날짜(거래일·거래일시) + 출금액/입금액 + 적요
  - 날짜·금액만 있는 표: 음수 = 지출, 양수 = 수입
- 날짜: `2026-11-13`, `2026.11.13`, `2026/11/13`, `20261113`, `26.11.13`, 시간이 붙어도 됨. 금액: 쉼표·원·₩·괄호 음수
- 글자 인코딩: UTF-8 이 아니면 **CP949**(한국 은행·엑셀 기본)로 읽는다. PC 앱 런타임에 `jdk.charsets` 포함
- 계좌 열이 없으면 화면에서 고른 **기본 계좌**(처음엔 생활비 계좌 중 첫 번째)로 넣는다. 이체는 두 계좌 이름이 앱과 맞아야 한다
- 카테고리는 이름이 같은 것에 연결, 없으면 미분류. 잔고 조정 줄은 가져오지 않는다
- 저장한 거래의 출처는 `IMPORT`. 한 트랜잭션으로 저장해 중간 실패 시 하나도 저장되지 않는다

## ⚠️ 확인이 필요한 규칙 (제안 기본값으로 구현)
1. ~~중복 판정~~ → Phase 2-5에서 **재확인 방식으로 확정**: 중복으로 보이는 줄은 안내를 띄우고, 사용자가 "중복 아님"을 누르면 남긴다
2. **날짜로 상태 결정**: 상태 열이 없으면 오늘 이후 = 예정, 오늘·과거 = 완료
3. **부호 규칙**: 유형 열이 없으면 음수 = 지출, 양수 = 수입

# Phase 2-5: 새 디자인 · 색 직접 지정 · 입력 편의 (2026-11-13)

## 사용자 결정
- CSV 중복: 자동으로 버리지 않고 **재확인 안내** → "중복 아님 · 가져오기"를 누르면 남긴다(모두 중복 아님 / 모두 건너뛰기 가능)
- 이체 이름: **"저축 및 이체"**

## 디자인 ("장부" 테마, 투두메이트 모양에서 변경)
- 옅은 회색 종이 배경 + 흰 카드(다크: 짙은 남색 계열), 잉크 네이비 주 색, 청록 강조
- 섹션은 카드로 묶고 머리에 색 막대 + 제목 + "＋ 추가" 알약(알약 전체가 눌림)
- 칩·버튼은 둥근 사각형, 2~4개 선택은 꽉 찬 분할 버튼, 스위치는 일반 스위치 모양
- 거래 줄: 완료 = 카테고리 색 칸 + 첫 글자, 예정 = 예정 색 빈 원(누르면 완료), 취소 = 회색 ×
- 캘린더 칸: 날짜(오늘 = 주 색 칸, 고른 날 = 옅은 주 색) + 상태 점(완료·예정 개수·반복 ↻)
- 하단 탭: 고른 탭 아이콘 뒤에 옅은 주 색 알약
- **홈 순서 정리**: 요약(사용 가능 금액·기간·예산 사용·수입/소비/예정) → 빠른 입력(지출·수입·저축 및 이체) → 예정 거래 → 최근 거래 → 남은 예산 → 잔고
- 거래 입력 순서: 유형 → 금액 → 카테고리 → 계좌 → 상태·날짜 → 메모
- 설정 순서: 회계 기간 → 분류 → 화면 → 색상 → 알림 → 데이터

## 색 직접 지정 (설정 → 색상)
- 주 색·강조 색·수입·지출·저축 및 이체·예정을 **색 코드(#RRGGBB)**로 입력하거나 추천 색에서 고른다. 기기별로 저장, "기본값으로" 가능
- 밝은 주 색을 고르면 버튼 글자가 자동으로 검정이 된다
- 카테고리 색도 카테고리 편집에서 색 코드로 입력할 수 있다

## 기능
- **화면 전환 잔상 제거**: 화면마다 불투명 배경 + 누름 표시를 손을 떼는 즉시 지움(물결 효과가 다음 화면까지 남지 않음)
- **캘린더 + 버튼**: 캘린더에서 고른 날짜로 입력이 시작된다. 날짜 아래 "11월 13일 (금) 수입·지출 추가" 버튼은 버튼 전체가 눌린다
- **기록 메뉴에서 유형 바꾸기**: 거래를 누르면 지출/수입/저축 및 이체를 바로 바꿀 수 있고, 저축 및 이체는 넣을 자산을 고른다(원래 계좌 유지, 카테고리는 미분류로)
- **입력 화면에서 바로 추가**: 계좌 목록 끝 "+ 새 계좌"(저축 및 이체의 넣을 자산은 저축 계좌로 생성), 카테고리 목록 끝 "+ 카테고리"
- **카테고리 삭제**: 쓰던 거래·반복 거래는 미분류로 남고(잔고 그대로), 그 카테고리 예산은 함께 삭제. 지우기 전에 영향받는 건수를 보여 준다. 보관도 계속 가능
- **알림 밀어서 닫기**: "완료 처리했습니다" 같은 알림을 옆으로 밀면 사라진다
