# 설계: todo mate 클론 (todo mate의 핵심 기능을 다시 만든 앱)

근거: `replica/recon.md`, `replica/features.csv`, 참고 스크린샷 27장 (`replica/screens/`)
목표: 1단계는 안드로이드에서 혼자 쓰는 기능, 2단계는 친구 기능, 그 뒤에 iOS
작성일: 2026-11-03

## 스택

한 줄 요약: **Expo(React Native, TypeScript) 앱 + 휴대폰 안 SQLite + Supabase(Postgres, 로그인, 파일 저장).** 따로 운영하는 서버는 없다.

| 층 | 선택 | 이유 |
| --- | --- | --- |
| 앱 | **Expo (React Native) + TypeScript**, 화면 이동은 Expo Router | 코드 하나로 안드로이드를 먼저 내고 iOS를 나중에 낼 수 있다. 자료와 예제가 가장 많아 공부용으로도 좋다 |
| 스타일 | React Native `StyleSheet` + 디자인 토큰 파일(`theme.ts`) | 스크린샷과 픽셀 단위로 맞추려면 값을 직접 쓰는 편이 정확하다. 다크/라이트 두 벌을 토큰으로 바꿔 끼운다. 나중에 내 디자인으로 바꿀 때도 토큰만 고치면 된다 |
| 그림 | `react-native-svg` | 클로버 체크박스와 날짜 표시를 직접 그린다. 여러 카테고리를 나눠 칠하는 모양도 SVG로 만든다 |
| 아이콘 | 오픈소스 아이콘 세트(예: Lucide) | 원본 아이콘 파일은 쓰지 않고 비슷한 모양으로 대신한다 |
| 휴대폰 안 저장 | **expo-sqlite + Drizzle ORM** | 오프라인에서도 바로 쓰고 바로 보인다. 화면은 항상 로컬 DB를 읽고, 서버와는 뒤에서 맞춘다 |
| 서버 데이터베이스 | **Supabase Postgres** | 무료 요금제로 시작할 수 있다. 행 수준 보안(RLS)으로 "본인 데이터만"을 데이터베이스가 직접 지킨다 |
| 로그인 | **Supabase Auth**: Google 로그인 + 이메일 | 원본처럼 소셜 로그인. 기기를 바꿔도 같은 계정으로 동기화된다 |
| 파일 | **Supabase Storage** | 프로필 사진, 할 일 인증 사진, 일기 사진 |
| 알림 | **expo-notifications 로컬 예약 알림** | 할 일 시간 알림과 매일 리마인더는 휴대폰이 스스로 울린다. 서버 없이 오프라인에서도 동작 |
| 홈 화면 위젯 | `react-native-android-widget` | 안드로이드 위젯을 React 코드로 만들 수 있다 |
| 결제 | 없음 | 개인/학습용이라 프리미엄 구독은 만들지 않는다 (기능표에서 could) |
| 이메일 | Supabase 기본 메일 (로그인용만) | 그 밖의 메일은 보내지 않는다 |
| 정기 작업 | Supabase `pg_cron` 1개 | 지운 지 30일 지난 행을 실제로 삭제 |
| 빌드와 배포 | **EAS Build**(Expo 클라우드 빌드) → APK를 내 폰에 설치, 나중에 Play 스토어 | 위젯과 알림은 Expo Go 앱으로는 확인이 안 돼서 개발용 빌드가 필요하다 |

고려했지만 고르지 않은 것:
- **Kotlin + Jetpack Compose**: 안드로이드만 보면 위젯과 성능이 가장 자연스럽지만, iOS를 다시 처음부터 만들어야 한다.
- **Flutter**: 좋은 선택이지만 Dart라는 언어를 새로 배워야 하고, 이 스킬 묶음(replica)의 예제는 TypeScript 기준이다.

## 스키마

테이블 8개(1단계) + 4개(2단계 설계만). 접근 권한: **Postgres RLS**. 전체 SQL은 `replica/schema.sql`.

| 테이블 | 내용 | 화면 |
| --- | --- | --- |
| `profiles` | 닉네임, 자기소개, 프로필 사진, 상태 이모지 | S02, S03 |
| `user_settings` | 설정 → 화면의 18개 값. 기본값은 사용자 스크린샷 값 | S12d |
| `categories` | 이름, **색상 코드 `#RRGGBB`**(직접 입력), 공개설정 4단계, 순서, 종료 여부 | S06, S06b, S06c, S06d |
| `routines` | 시작·종료 날짜, 반복(매일, 간격, 매주, 격주, 매월, 매년)과 세부값, 시간, 메모, 수동 추가 | S07, S07b, S07c, S07d |
| `todos` | 날짜, 완료, 메모와 메모 나만 보기, 알림, 인증 사진, 타이머, 어느 루틴의 몇 일 회차인지 | S03, S04, S05, S05a~c, S08 |
| `ddays` | 이름, 고정 날짜/반복, 날짜, 나만 보기, 순서 | S21, S21b |
| `reminders` | 매일 알림 시간 | S22, S22b |
| `diaries` | 하루 하나, 감정 이모지, 글, 공개 범위, 배경색, 사진 | S09, S10 |
| (2단계) `follows`, `category_viewers`, `reactions`, `notifications` | 팔로우, 일부 공개 대상, 이모지 반응, 알림 | S15~S19 |

설계에서 정한 것:
- **id는 휴대폰이 만든다.** 오프라인에서 만든 할 일도 서버와 같은 id를 쓴다.
- **지우기는 `deleted_at` 표시.** 다른 기기가 "지워졌다"는 사실을 동기화로 받아 가야 하기 때문. 30일 뒤 정리 작업이 실제로 지운다.
- **"그날"은 `date` 타입**(시간대 없이 사용자가 보는 날짜 그대로), 그 밖의 시각은 `timestamptz`(UTC).
- **루틴 회차는 행을 미리 만들지 않는다.** 앱이 규칙으로 계산해서 보여주고, 사용자가 회차를 체크·수정·이동·삭제하는 순간 `todos`에 `routine_id + routine_date` 행을 만든다. 같은 회차가 두 번 생기지 않도록 데이터베이스에 고유 인덱스를 걸었다.
- **루틴을 지워도 지난 기록은 남는다**(`on delete set null`). **카테고리를 삭제하면** 할 일과 루틴도 같이 지워진다(원본 설명 문구 그대로).
- **종료한 카테고리**에는 새 할 일 추가를 데이터베이스가 막는다.
- **할 일과 루틴은 내 카테고리에만** 들어갈 수 있다(트리거로 확인).
- **가입하면** 프로필과 설정 행이 자동으로 만들어진다.

검증: 로컬 Postgres 16에 Supabase의 `auth`, `storage`를 흉내 낸 최소 스키마를 깔고 `schema.sql`을 실행했다. 아래를 확인했다.
- 가입 트리거로 프로필이 만들어짐
- 잘못된 색상 코드 거부
- 다른 사람 이름으로 넣기 거부(RLS)
- 요일 없는 매주 루틴 거부
- 같은 루틴 회차 중복 거부
- 종료된 카테고리에 추가 거부
- `pull_changes` 동작
- 다른 사용자에게 내 할 일이 안 보임

이 과정에서 요일 없는 매주 루틴이 통과되던 버그를 하나 찾아 고쳤다. 실제 Supabase 프로젝트에서는 아직 실행하지 않았다.

## API

서버 코드를 따로 두지 않는다. 앱은 Supabase 클라이언트로 테이블에 직접 읽고 쓰고, RLS가 권한을 지킨다. 화면은 항상 **휴대폰 안 SQLite**를 읽고 쓰며, 아래 동기화가 뒤에서 서버와 맞춘다.

| 호출 | 하는 일 | 누가 | 입력 | 출력 | 흐름 |
| --- | --- | --- | --- | --- | --- |
| Auth `signInWithIdToken` (Google) / `signInWithOtp` (이메일) | 로그인 | 누구나 | Google 토큰 / 이메일 | 세션 | 가입, 로그인 |
| RPC `pull_changes(since)` | 마지막 이후 바뀐 내 행 전부(지운 행 포함) | 로그인한 본인 | 마지막 서버 시각 | 테이블별 행 목록 + 서버 시각 | F09 동기화 |
| `upsert` 테이블별 (categories, routines, todos, ddays, reminders, diaries, profiles, user_settings) | 휴대폰에서 바뀐 행 올리기 | 본인 | 바뀐 행들 | 성공/실패 | F01~F07 전부 |
| Storage `upload` / `remove` | 사진 올리기와 지우기 (`{user_id}/{id}.jpg`) | 본인 | 사진 파일 | 경로 | F03c 사진 인증, S02, S09 |
| Storage `createSignedUrl` | 비공개 사진 보기 | 본인 | 경로 | 1시간짜리 주소 | S03, S05b |
| Edge Function `delete-account` | 계정과 모든 데이터, 파일 삭제 | 본인 | 없음 | 성공 | S12 계정 |

흐름별로 쓰는 호출 (모두 로컬 저장이 먼저, 서버는 동기화):

| 흐름 | 로컬에서 하는 일 | 서버로 가는 것 |
| --- | --- | --- |
| F01 할 일 추가·완료 | `todos` 행 추가, `is_done`/`done_at` 변경 | todos upsert |
| F02 카테고리 | `categories` 추가·수정·정렬·종료·삭제, 이관은 할 일의 `category_id` 일괄 변경 | categories, todos upsert |
| F03 미루기, 복사 | 날짜 바꾸기는 `date` 변경, 내일/다른 날 또 하기는 새 행 복사 | todos upsert |
| F03c 메모, 알림, 타이머, 사진 | 해당 칸 변경, 알림은 로컬 예약, 사진은 업로드 대기열 | todos upsert, Storage |
| F04 루틴 | `routines` 추가·수정, 회차 체크 시 `todos` 행 생성 | routines, todos upsert |
| F06 일기 | `diaries` 하루 하나 | diaries upsert, Storage |
| F07 디데이 | `ddays` 추가·정렬 | ddays upsert |
| 리마인더 | `reminders` 추가, 매일 로컬 알림 예약 | reminders upsert |
| F08 위젯 체크 | 위젯이 로컬 DB를 직접 바꾸고 다음 동기화 때 올림 | todos upsert |

들어오는 웹훅: 없음. 나가는 웹훅: 없음.
정기 작업:
- `purge-deleted`(매일 4시 UTC, pg_cron): `deleted_at`이 30일 지난 행과 그 사진 파일을 삭제.
- 앱 안의 동기화: 앱을 열 때, 화면으로 돌아올 때, 무언가 바꾼 뒤 2초 후, 그리고 켜져 있는 동안 1분마다.

2단계에 추가할 것: 친구 행 읽기 정책, `follows`/`reactions` 테이블, 반응이 생기면 상대에게 푸시 알림을 보내는 Edge Function(Expo Push).

공식 공개 API만 쓴다. 원본 앱의 서버 주소나 비공개 API는 쓰지 않는다.

## 까다로운 부분

- **시간대와 날짜**: 할 일의 "그날"은 사용자가 보는 날짜(`date`)로 저장해서, 해외에 가도 11월 3일 할 일은 11월 3일에 있다. 완료 시각과 알림 시각만 UTC로 저장하고, 보여줄 때 휴대폰 시간대로 바꾼다. 자정이 넘어가면 홈의 "오늘"과 위젯을 다시 그려야 한다.
- **루틴 규칙 계산**: 매월 31일은 31일이 없는 달에는 건너뛴다(원본 확인 필요). 격주는 시작일이 있는 주를 기준으로 센다. 간격은 시작일부터 n일마다. 종료일이 지나면 "진행 중"이 아니다. 이 계산 함수는 시험 코드로 꼼꼼히 확인한다.
- **같은 일을 두 번 받기**: 동기화는 여러 번 돌아도 결과가 같아야 한다. upsert는 id 기준이라 두 번 올려도 괜찮다. 루틴 회차는 고유 인덱스가 중복을 막는다. 두 기기가 같은 회차를 동시에 만들면, 두 번째는 실패하고 서버 행을 받아 와서 합친다.
- **동시 수정**: 같은 할 일을 두 기기에서 고치면 나중에 도착한 쪽이 이긴다(행 단위). 혼자 쓰는 앱이라 이 정도로 충분하다. 2단계 반응은 행이 따로라 부딪히지 않는다.
- **동기화 빈틈**: 서버 시각 기준으로 받아 가므로, 동시에 커밋 중이던 행을 놓칠 수 있다. 요청할 때 마지막 시각에서 몇 초 앞당겨 겹치게 받고 id로 덮어쓴다.
- **오프라인**: 모든 화면이 로컬 DB만 보면 자연스럽게 해결된다. 사진은 올리기 대기열에 넣고 온라인이 되면 올린다. 그때까지는 휴대폰 안 파일을 보여준다.
- **종료된 카테고리와 오프라인**: 다른 기기에서 카테고리를 종료한 줄 모르고 오프라인에서 할 일을 추가하면 서버가 거부한다. 앱은 거부된 행을 표시하고 사용자에게 알린다.
- **타이머**: 앱이 꺼져도 시간이 이어지도록 "시작 시각"만 저장하고, 지난 시간은 그때그때 계산한다. 멈출 때 `timer_seconds`에 더한다.
- **알림**: 안드로이드 13 이상은 알림 권한을 따로 물어야 하고, 정확한 시각 알림은 정확한 알람 권한이 필요할 수 있다. 기기마다 자기 알림을 예약하므로, 동기화로 알림이 바뀌면 예약을 다시 한다. 로컬 예약 알림 개수에는 한도가 있어서 앞으로 며칠치만 예약한다.
- **위젯**: 위젯은 앱과 별개로 실행된다. 로컬 DB를 같이 쓰도록 하고, 위젯에서 체크하면 앱이 다음에 열릴 때 동기화한다.
- **파일 크기**: 사진은 올리기 전에 긴 변 1600px, JPEG 품질 80%로 줄인다. Storage 무료 한도 안에 머무르기 위해서다.
- **삭제와 개인정보**: 설정의 계정 삭제는 모든 행과 사진 파일을 실제로 지운다(Edge Function).
- **2단계 공개 범위**: 지금 RLS는 "본인만"이다. 친구 기능을 붙일 때 읽기 정책을 추가하는데, 할 일은 카테고리의 공개설정을 따르고, 메모는 `memo_is_private`, 일기와 디데이는 각자의 공개 범위를 따른다. 이 규칙은 데이터베이스 정책 한 곳에 모아 둔다.

## 개발 순서

**1. 수직 슬라이스 (뼈대를 처음부터 끝까지)**
- 화면: S01 로그인 → S03 홈(캘린더 + 카테고리 + 할 일) → S04 인라인 입력 → 체크로 완료
- 테이블: profiles, user_settings, categories, todos
- 호출: Google 로그인, todos/categories upsert, `pull_changes`
- 완료 기준: 폰 두 대(또는 폰과 에뮬레이터)에서 같은 계정으로 할 일을 추가하고 체크하면, 다른 쪽에도 나타나고 캘린더 클로버가 바뀐다. 오프라인에서 추가한 것도 나중에 올라간다. 디자인은 이 단계에서 대충이어도 된다.

**2. 필수 기능 (`features.csv`의 must)**
- 2a 홈 완성: 클로버의 모든 상태, 월/주 전환, 오늘 표시, 일요일·토요일 색, 다크/라이트 테마 → S03
- 2b 할 일 메뉴: S05 바텀 시트, 수정·삭제, 메모(S05a), 날짜 바꾸기, 내일/다른 날 또 하기, 더블 탭 편집, 순서 바꾸기 → todos
- 2c 카테고리: S06m 상단 메뉴, S06 목록과 드래그, S06b 편집, S06c 공개설정, **S06d 색상 코드 입력**, 종료와 삭제 → categories
