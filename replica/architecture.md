# Architecture: Talestopia Tycoon (Realm Grinder의 시스템 구조를 다시 만든 게임)

근거: `replica/recon.md`(시스템·확인된 수치), `replica/features.csv`, `replica/screens/`(사용자 녹화 영상에서 뽑은 원작 화면, 출시물에 포함 금지).

이 게임은 **서버 없는 1인용 오프라인 게임**이다. 그래서 웹 서비스용 기본 구성(DB, 로그인, 결제 서버, 메일)은 대부분 해당 없고, 그 자리를 **저장 데이터 구조**와 **게임 엔진 액션**이 대신한다.

## Stack

| layer | choice | why |
| --- | --- | --- |
| 언어 | TypeScript | 진영·업그레이드 수백 개의 데이터를 타입으로 묶어야 실수가 안 난다 |
| 빌드 | Vite | 설정이 거의 없고, 빌드 결과가 정적 파일이라 앱 포장이 쉽다 |
| 화면 | DOM + CSS (패널·버튼) / `<canvas>` (영토 지도) | 패널은 DOM이 접근성·텍스트에 유리, 지도는 픽셀 아트라 캔버스가 정확 (`image-rendering: pixelated`) |
| 큰 수 | `break_infinity.js` | 원작은 1e27 보석, 1e300+ 금화까지 간다. JS 기본 숫자는 1.8e308에서 끝난다 |
| 엔진 | 순수 TS 모듈 (DOM 없음) | 지금 프로토타입처럼 규칙을 화면과 분리 → 테스트 가능, 밸런스 시뮬레이터 재사용 |
| 테스트 | Vitest + Playwright | 엔진 단위 테스트 + 화면 클릭 테스트 (현재 node:test 14개는 이전) |
| 모바일 | Capacitor (Android) | 웹 빌드를 그대로 앱으로 감쌈. 이 환경에 Android SDK 있음 |
| 저장 | localStorage → Capacitor Preferences | 기기 저장. 저장 코드 내보내기/불러오기 유지 |
| 클라우드 저장 | Google Play Games Saved Games (나중) | 원작 옵션 화면에 있는 기능 (S15), should |
| 결제·광고 | Google Play Billing + AdMob (Capacitor 플러그인, 나중) | 원작 상점(S16)·점술 광고(S17) 자리. 상품 구성은 새로 설계 |
| 그래픽 | 직접 만든 픽셀 아트 PNG 스프라이트 시트 | 원작 그림은 쓰지 않음. 기준 해상도 16·32px 그리드 |
| 배포 | Play Console 내부 테스트 → 정식 | |

## Schema (저장 데이터)

DB 대신 저장 파일 하나. 테이블 = 저장 데이터의 묶음. 타입 정의는 `replica/save-schema.ts`.
접근 규칙: 1인용이라 없음. 대신 **불러오기 때 검증**(버전·필드 누락 보정·숫자 범위)이 그 역할을 한다.

## API (엔진 액션)

서버가 없으므로 "API"는 엔진이 공개하는 순수 함수다. 모든 액션은 `(state, now, rng?) => result`이고 화면은 이것만 부른다.

| action | 하는 일 | 입력 | 결과 | flow |
| --- | --- | --- | --- | --- |
| `tick` | 시간 경과: 건물·조수 생산, 마나 회복, 진영 코인 자동 발견, 자동 시전 | now | 획득량 | 전체 |
| `click` | 지도 탭: 탭 보상 + 진영 코인 10% 확률 | now, rng | 금화, 코인 | F01 |
| `buyBuilding` | 1/10/100/최대 구매, 가격 = 기본가×1.15^n | id, amount | ok | F01 |
| `buyAllBuildings` | '모두 구매' | — | 산 개수 | F01 |
| `buyUpgrade` / `buyAllUpgrades` | 업그레이드 구매 | id | ok | F02 |
| `buyAlignment` | 성향 증표 (금화 25,000) | good/evil/neutral | ok | F02 |
| `joinFaction` | 진영 조약 (진영 코인 20) | factionId | ok | F02 |
| `castSpell` | 주문 시전 | spellId | 효과 | F03 |
| `setAutocast` | 자동 시전 우선순위·임계값 | spellId, tier | — | F03 |

| `reincarnate` | 환생 (보석 1e27 × 1000^R) | bloodline | ok | F06 |

## The parts that bite

- **큰 수**: 금화가 1e300을 넘는다. 엔진의 모든 금화·가격 계산을 처음부터 `Decimal`로. 나중에 바꾸면 전부 다시 써야 한다.
- **시간**: 기기 시계를 앞으로 돌리면 오프라인 수익을 무한으로 받는다. 오프라인 최대 시간 상한 + 시계가 뒤로 가면 0 처리.
- **오프라인 계산**: 주문은 오프라인에 시전되지 않는다(원작 규칙). 오프라인 동안 지속 효과가 끝나는 시점을 나눠 계산.
- **성능**: 업그레이드 수백 개 × 초당 10틱. 생산 배율은 구매·시간 변화 때만 다시 계산하고 캐시.
- **저장 이전**: 데이터가 계속 늘어나므로 저장 버전 + `migrate` 함수를 처음부터.
- **화면 크기**: 원작은 1080×2340 세로 고정. 우리는 360~430px 폭 기준, 지도 캔버스는 정수 배율로만 확대(픽셀 뭉개짐 방지).
- **결제 규정**: 루비 같은 화폐를 팔면 Google Play 결제 필수, 확률형(발굴) 상품을 팔면 확률 공개 의무. 출시 전 정책 확인.

## Build order

1. **Vertical slice** — S01 + S02 + S03 일부. 영토 지도(임시 픽셀 그림) 탭 → 금화 → 공통 건물 3종 구매 → 성향 증표 → 진영 1개 가입 → 진영 주문 1개 → 퇴위 → 보석 보너스 확인. TS + Vite + Decimal 엔진 + Capacitor 안드로이드 빌드까지 한 번에 확인.
2. **Must-haves** (`features.csv` must 22개)
   - 건물: 11단계 × 3성향, 건물 업그레이드(5/25/75/150/200…), 조수, 최대·모두 구매 (S02)
   - 진영: 기본 6 + 중립 3, 진영당 업그레이드 12개, 진영 코인, 진영 주문, 성향 주문, 공통 주문 (S03, C)
   - 퇴위·보석 공식, 업적, 오프라인, 저장 (S03, S08, S14, S15)
   - 픽셀 아트 1차: 건물 아이콘 31, 진영 아이콘 9, 주문 아이콘 15, UI 프레임, 영토 지도
3. **Should-haves** — 자동 시전, 왕실 교환(S09), 통계, 환생·혈통, 도전(S13), 연구, 발굴·유물(S12), 숫자 표기 옵션, 사운드
4. **Could-haves** — 프리스티지·용병 진영, 승천, 상점(S16)·점술 광고(S17)·이벤트(S18), 클라우드 저장
5. **Fixes from replica-entrepreneur** — 원작 사용자 리뷰에서 나온 불만 해결 (아직 실행 안 함)
