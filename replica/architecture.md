# 설계: Looin Idle (방치형 횡스크롤 RPG, 1월드부터 단계 확장)

기준 문서: `recon.md`, `features.csv`. 참고 화면: `screens/S03-town-hud.jpg`(저장소에는 올리지 않음).
이미 있는 것: `game/` — TypeScript + Phaser + Capacitor 클라이언트, 화면과 분리된 규칙 코드(`game/src/core`), 테스트 23개.

## 스택

| 층 | 선택 | 이유 |
| --- | --- | --- |
| 클라이언트 | TypeScript + Phaser 3 + Vite (현재 그대로) | 이미 동작하고, 웹이라 PC도 같은 빌드로 나간다 |
| 모바일 포장 | Capacitor (Android → iOS) | 현재 그대로. iOS는 같은 방식으로 추가 |
| 게임 규칙 | `game/src/core` 를 독립 패키지 `packages/core` 로 분리 | 클라이언트와 서버가 **같은 코드**로 계산해야 검증이 된다 |
| 서버 | Node + TypeScript (Fastify) 한 개 | core를 그대로 import. 마이크로서비스 없음 |
| 실시간 | 같은 서버의 WebSocket (`ws`) | 같은 맵 플레이어 표시·채팅 전용. 전투는 실시간 동기화하지 않는다 |
| 데이터베이스 | Postgres (Supabase) 하나 | 관리형, 무료 구간, 인증과 한 곳 |
| 인증 | Supabase Auth: 게스트(익명) → Google/Apple 연동 | 설치 직후 바로 플레이, 나중에 계정 연결 |
| 결제 | Google Play 결제 / App Store 결제 (출시 직전) | 모바일 스토어 규정상 필수. Stripe는 쓰지 않는다 |
| 작업 | Supabase 예약 작업(pg_cron) | 채팅·명령 기록 정리 |
| 호스팅 | 서버: Fly.io(서울 근처 리전 1대), 웹: 정적 호스팅 | 상시 WebSocket이 필요해 서버리스가 아닌 상주 프로세스 |

저장소 구조(목표):

```
packages/core     규칙·데이터·공식 (DOM/Node 의존 없음)   ← 지금의 game/src/core
game/             클라이언트 (렌더·UI·입력)
server/           API + WebSocket
replica/          정찰·설계 문서, schema.sql
```

## 권한 모델 (이 게임에서 가장 중요한 결정)

방치형이라 실시간 전투를 서버가 돌릴 필요가 없습니다. 대신 **보상이 생기는 순간**만 서버가 계산합니다.

1. **방치 보상**: 서버가 `last_active_at`(서버 시계)과 저장된 캐릭터 상태로 `computeAfk`를 직접 실행합니다. 클라이언트가 보내는 값은 없습니다.
2. **접속 중 플레이**: 클라이언트가 화면에서 전투를 돌리고, 일정 간격으로 "이 시간 동안 처치 N, 채집 M"을 보고합니다. 서버는 같은 캐릭터 상태로 **그 시간에 가능한 최대치**(core의 처치 상한 공식)를 계산해 넘는 부분을 잘라내고, 드롭·경험치는 서버 난수로 다시 굴려 지급합니다.
3. **그 밖의 행동**(제작, 장착, 특성, 창고, 퀘스트, 전직): 클라이언트가 명령만 보내고 서버가 core 함수로 적용합니다.
4. **오프라인 플레이**: 연결이 끊기면 로컬에서 계속 진행하되, 다시 연결되면 서버 상태가 기준입니다. 끊긴 시간은 방치로 처리합니다.

모든 명령은 클라이언트가 만든 ID를 달고, 서버는 같은 ID를 두 번 처리하지 않습니다.

## 스키마

표 7개. 접근 규칙: **RLS로 본인 것 읽기만 허용, 쓰기는 전부 서버(service role)**. 전문은 `schema.sql`.

| 표 | 내용 | 비고 |
| --- | --- | --- |
| accounts | 코인·보석·가족 레벨·창고 칸 수·계정 공용 진행(jsonb) | auth.users 와 1:1 |
| characters | 슬롯·이름·직업·레벨·맵·`last_active_at`·상태(jsonb) | (account_id, slot) 유일 |
| storage_items | 계정 공용 창고 | (account_id, item_id) 기본 키 |
| cards | 카드 보유 수 | 계정 공용 |
| commands | 처리한 명령 기록 | 중복 방지 + 부정 조사 |
| chat_messages | 채팅 | 7일 뒤 삭제 |
| purchases | 결제 영수증 | (store, store_txn_id) 유일 |

캐릭터 상태를 jsonb로 두는 이유: 한 캐릭터를 통째로 읽어 core에 넣고 통째로 다시 쓰는 흐름이 대부분이고, 시스템이 늘 때마다 표를 바꾸지 않아도 됩니다. 형식이 바뀌면 `state_version`으로 서버가 올려 줍니다(지금 `deserialize`가 하는 보충과 같은 방식).

## 클라이언트 구조 변경 (참고 화면 기준)

- **하단 바를 화면 전체 폭으로**: 왼쪽 캐릭터 요약(이름·직업·레벨), 가운데 HP/MP/XP 세 줄, 오른쪽에 큰 사각 메뉴 버튼 한 줄(자동 / 공격 / 아이템 / 특성 / 도감 / 지도 / 채팅 / 메뉴). 지금의 왼쪽 위 HUD와 오른쪽 아래 버튼은 이 바로 합칩니다.
- **맵은 여러 층 + 로프**가 기본. 마을에도 층이 있고 시설(용광로·모루·상점·창고 상자·NPC·포탈)이 층마다 배치됩니다. 필요한 맵 데이터: 층(높이가 다른 지형 블록), 로프, 시설 위치, NPC 위치, 포탈.
- **지형이 떠 있는 발판이 아니라 땅 덩어리**: 위층은 아래가 흙으로 채워진 절벽 형태. 렌더러에 "채워진 지형" 그리기가 필요합니다.
- **NPC 머리 위 말풍선 표시**(퀘스트 가능/진행/완료), 다른 캐릭터(내 계정의 다른 캐릭터, 이후 다른 플레이어)가 맵에 서 있는 표시.
- UI 창은 전부 같은 창 틀 + 탭 구성으로 통일(`replica-design` 단계에서 토큰화).

## 조심할 부분

- **시간**: 방치 계산은 서버 시계만 씁니다. 기기 시계를 바꿔도 소용없게 `last_active_at`은 서버가 기록합니다. 표시용 시간만 기기 시간대.
- **중복 처리**: 모든 쓰기에 `commandId`. 응답을 못 받은 요청을 다시 보내도 한 번만 적용됩니다. 결제 영수증도 `(store, store_txn_id)` 유일.
- **동시성**: 같은 계정을 두 기기에서 열면 `version`이 안 맞는 쪽이 거부되고 최신 상태를 다시 받습니다. 창고·코인처럼 계정 공용 값은 한 트랜잭션에서 계정 행을 잠그고 바꿉니다.
- **부정 방지**: 접속 중 보고는 상한으로 자르고, 반복해서 상한에 걸리는 계정은 `commands.flagged`로 표시만 합니다(자동 제재는 하지 않음).
- **오프라인**: 로컬 저장을 유지하되 서버와 다르면 서버가 이깁니다. 연결이 없을 때의 진행은 재접속 시 방치로 환산합니다.
- **실시간**: 위치는 초당 몇 번만 보내고 보간합니다. 맵당 표시 인원 상한을 두고, 서버 1대로 시작합니다.
- **저장 형식 변경**: 시스템이 늘 때마다 `state_version`을 올리고 올림 함수를 core에 둡니다. 테스트로 고정.
- **요청 제한**: 계정당 쓰기 요청 수를 제한(예: 초당 5). 채팅은 더 낮게.
- **개인정보 삭제**: 계정 삭제 시 `on delete cascade`로 전부 지워집니다. 결제 기록만 법적 보관을 위해 `restrict` — 삭제 전 익명화 절차가 필요합니다.
- **스토어 규정**: 다른 게임과 혼동될 이름·아이콘·스크린샷은 심사에서 걸립니다(`replica-brand`, `replica-launch` 단계에서 점검).

**1. 1월드 규칙 완성 (서버 없이, 로컬)** — 필수 기능 중 규칙에 해당하는 것부터.
   - 명중률, 방어력 임계값, 마나, 음식 → 전투 공식 구조를 정찰 지도대로
   - AFK 획득률 능력치, 생존력, 처치 상한, AFK 정보 창 (S09)
   - 대장 기술: 모루 생산·포인트 (S12), 모루 단계 탭과 레시피 해금 (S11)

   - 여러 층 마을과 시설 배치, 채워진 지형 렌더링, 상점 (S15)
   - 월드 보스와 다음 월드 관문 (S20), 월드 지도 (S18)
   - 하단 전체 폭 바로 UI 재배치 (S04)

**4. 함께 있는 느낌** — 같은 맵 플레이어 표시, 채팅.
   - 표: chat_messages. 경로: WS /live.

**5. 권장·선택 기능** — 2차 전직, 가족 보너스, 카드 장착 칸·세트, 작업판, 우표, 용광로, 퀘스트 목록, 추가 기술.

**6. 출시 준비** — 결제(표: purchases, 경로: /purchases/verify), 사운드, 아트 교체, iOS·PC.
